# GDPR 合规指引（Shadow Agent）

本指引面向以欧盟《通用数据保护条例》(GDPR) 为适用法律的部署方。Shadow Agent
是一个可自托管的安全网关：**部署方是数据控制者**，负责最终合规；本文映射
本产品代码库中已有的技术措施与仍需部署方完成的义务。

## 1. 角色划分

| 主体 | 角色 | 说明 |
| --- | --- | --- |
| Shadow Agent 部署方 | 数据控制者 | 决定处理目的与方式，承担 GDPR 主体责任 |
| 上游 LLM 提供商 | 处理者（或独立控制者） | 网关转发的 prompt/上下文会离开本系统，需与之签署数据处理协议 (DPA) |
| 控制台用户 / API 调用方 | 数据主体 | 其姓名、邮箱、请求内容可能构成个人数据 |

## 2. 个人数据映射（基于当前代码库）

| 存储位置 | 字段 | 数据类型 | 内置保护 |
| --- | --- | --- | --- |
| `console_users` | name, email | 身份信息 | 密码以 PBKDF2-SHA256（12 万轮）哈希存储，绝不明文 |
| `console_users` | password_hash | 凭证 | 盐值随机、仅存哈希 |
| `intercept_logs` / `audit_logs` | original_prompt / original_instruction | 可能含终端用户输入的个人数据 | 写入前经 `redact_text` 掩蔽 token/密钥/密码模式，超长截断 |
| `intercept_logs.details` / `alert_events.details` | 结构化明细 | 可能含 IP、工具参数 | 经 `sanitize_json` 递归掩蔽敏感键（authorization、api_key、password 等），深度限制 4 层 |
| `managed_api_keys` | created_by, last_used_by | 操作者邮箱 / 调用来源 IP | 原始密钥仅以 `pepper + SHA-256` 哈希存储，创建后不再可见 |

**数据最小化**是本产品的内置设计：拦截日志默认只保留脱敏摘录（`max_chars=500`），
结构化日志的列表长度截断为 50 项。

## 3. 合法利益与透明度

- 推荐处理基础：**合法利益**（网络与信息安全，GDPR 序言第 49 条）用于安全审计/
  入侵检测；**合同履行**（第 6(1)(b) 条）用于控制台账户管理。
- 义务：在隐私政策中披露"输入内容会被安全网关记录并脱敏存储"以及"转发给上游
  LLM 提供商"两类处理，并提供 Art. 13/14 告知文本。

## 4. 数据主体权利 (DSAR) 履行路径

| 权利 | 现有技术路径 | 响应建议 |
| --- | --- | --- |
| 访问 (Art. 15) | 管理员通过 `/api/v1/logs`、审计日志按 request_id 检索 | 导出与该用户/邮箱关联的记录 |
| 更正 (Art. 16) | `console_users` 姓名/邮箱可由管理员更新 | 数据库操作，无自助端点 |
| 删除 (Art. 17) | 删除 `console_users` 行 + 保留脱敏审计日志 | 审计日志经脱敏后通常可依 Art. 17(3)(b)/(e) 保留；未脱敏字段应清除 |
| 可携带 (Art. 20) | 日志 API 返回 JSON | 直接导出 |
| 反对/限制 (Art. 21/18) | 停用账户（is_active=false，JWT 立即失效） | 账户停用即停止处理 |

## 5. 数据保留（部署方必须决策）

网关**内置自动保留清理**（`app/retention.py`）：启动时执行一次，之后每小时
运行，按批次删除过期行，并在 `/metrics` 暴露 `shadow_agent_retention_purged_rows_total`。

| 环境变量 | 默认 | 作用 |
| --- | --- | --- |
| `SHADOW_AGENT_LOG_RETENTION_DAYS` | 180 | 全局默认保留窗口 |
| `SHADOW_AGENT_INTERCEPT_LOG_RETENTION_DAYS` | 继承全局 | 拦截日志保留期 |
| `SHADOW_AGENT_AUDIT_LOG_RETENTION_DAYS` | 365 | 审计日志保留期（问责记录，更长） |
| `SHADOW_AGENT_ALERT_RETENTION_DAYS` | 继承全局 | 告警事件保留期 |
| `SHADOW_AGENT_REPLAY_RETENTION_DAYS` | 继承全局 | 重放记录保留期 |
| `SHADOW_AGENT_RETENTION_CLEANUP_INTERVAL_SECONDS` | 3600 | 清理周期（最小 60） |

任一表设为 `0` 或负数即永久保留该表。部署方义务：

1. 按自身监管要求设定各表保留期（安全日志通常 90 天–1 年）；
2. 数据库文件所在卷启用静态加密；销毁阶段连同卷一起销毁；
3. 若日志同时外送集中日志系统，其保留策略需单独配置（内置清理仅作用于
   本地数据库）。

## 6. 跨境传输评估

配置 `SHADOW_AGENT_UPSTREAM_BASE_URL` 后，prompt（可能含个人数据）将被转发到
上游提供商。若该提供商在欧盟以外：

- 评估标准合同条款 (SCC) 或等效机制（EU-US Data Privacy Framework）；
- 在隐私政策中披露接收方与目的；
- 若无法满足，可在防火墙层面仅放行欧盟区域的上游端点。

## 7. 安全措施基线（已内置 / 部署方责任）

| 措施 | 状态 |
| --- | --- |
| 传输加密 | 部署方责任：必须在反向代理/负载均衡器终止 TLS |
| 静态加密 | 部署方责任：卷/磁盘加密 |
| 密钥分离（JWT 签名密钥、API key pepper、静态密钥各自独立） | 已内置，环境变量强制 |
| 登录暴力破解锁定、枚举防护（时间均衡 + 统一报错） | 已内置 |
| 敏感信息掩蔽（日志写入前） | 已内置 |
| 访问控制（4 角色 RBAC + 审批工作流） | 已内置 |
| 管理操作审计 | 已内置 |

## 8. DPIA 快速筛查

以下任一条件成立时，建议先完成数据保护影响评估：

- 处理特殊类别数据（健康、生物识别等）经过网关；
- 大规模系统性监控终端用户通讯；
- 上游 LLM 提供商位于欧盟以外且无 SCC。

筛查结论为低风险时，将本文件第 2、5、6 节的决策记录归档即可作为最小文档。
